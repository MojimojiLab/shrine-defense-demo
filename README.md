## 開始之前

### 準備三樣東西

1. **ChatGPT 帳號**。我們用的是付費版 Plus。免費版也勉強可以，只是額度比較少，不能反覆修改太多次喔。
2. **這裡的檔案**。按[下載整包專案 ZIP](https://github.com/MojimojiLab/shrine-defense-demo/archive/refs/heads/main.zip)，解壓縮。如果只需要某一個檔案的話，可以從上面的列表點進那個檔案，再按右上角的下載圖示。
3. **一張你喜歡的角色圖**。沒有的話，就用整包專案裡的[角色海報](%E8%A7%92%E8%89%B2%E6%B5%B7%E5%A0%B1/Machakon-Poster-2026.jpg)。

### 打開 ChatGPT 的「工作」模式

用電腦的瀏覽器打開 [chatgpt.com](https://chatgpt.com)，開一個新對話，把最上面的開關從「對話」切到「**工作**」（也就是 Codex）。

為什麼要切換？因為「工作」是專門拿來做事的模式，它會把你上傳的檔案跟它做好的圖集中管理，比較不會做到一半就忘記。

> 我們選的模型是 GPT-6.1 Sol，在輸入框右下角可以切換。ChatGPT 的畫面和模型名稱會改版，長得不太一樣也沒關係，找到意思相同的按鈕就好。

### 每一步都是同樣的四個動作

1. **上傳**：這一步要用的檔案，拖進輸入框（大部分的步驟不用）。
2. **貼上**：滑鼠移到灰色框框上，右上角會出現複製按鈕。按一下，貼到 ChatGPT，送出。
3. **檢查**：做完之後，對照「檢查清單」。少了什麼，直接用說的請它改。
4. **下一步**：過關了再往下。

⚠️ **七步全部在同一個對話串裡做**，不要每一步開一個新的。這樣 AI 才記得前面做過什麼。

> AI 每次做出來的都不一樣，所以你的一定會和我們的不同。長得不像沒關係，檢查清單有過就可以。卡住了，每一步都有[存檔點](%E5%AD%98%E6%AA%94%E9%BB%9E/)：我們做好的東西，下載了接著做就好～

## 第 1 步：規劃

**目標**：先不做遊戲，先叫 AI 寫規劃給你看。

**要上傳**：[遊戲企畫.txt](%E9%81%8A%E6%88%B2%E4%BC%81%E7%95%AB.txt)（想做自己的題材，先看[換成你自己的題材](#換成你自己的題材)）

**第 1 則提示詞**

```text
請讀取這個遊戲企畫，然後使用 Pixi.js，製作一個網頁版的遊戲。
先從規劃開始，告訴我你會怎麼做。
```

![第 1 步的畫面](%E5%9C%96%E8%A7%A3/step1-send.jpg)

① 切到「工作」 → ② 把 `遊戲企畫.txt` 拖進來 → ③ 貼上提示詞 → ④ 送出

**你會看到**：AI 寫出一份規劃，還沒有寫程式。我們那次它決定了這些：

- 神社被打 10 次就失敗
- 一共 6 波敵人
- 升級的時候三選一
- 巫女碰到敵人不會死，只會被擊退、變慢

企畫裡都沒有寫這些，是 AI 自己補的。不過這次它補在**你看得到的地方**，不喜歡就可以改。

<details>
<summary>📄 看 AI 那次寫的整份規劃</summary>

<br>

我讀完《神社保衛戰》了。我會把它做成**俯視角、以移動與守點為核心的自動戰鬥遊戲**：玩家操控巫女，在外出收集經驗與回防神社之間做選擇。

以下是規劃；企畫未指定的數值與規則，先採用可調整的初版設定。

**1. 核心玩法**

- 神社固定在場地中央，敵人從四周出現並向神社前進。
- 玩家用 **WASD／方向鍵**移動巫女，手機則使用虛擬搖桿。
- 巫女自動施放技能，玩家專注於走位、攔截敵人與拾取經驗。
- 擊敗敵人掉落經驗光玉，靠近後吸收。
- 升級時暫停戰鬥，提供 **三選一強化**。
- 最終 BOSS 被擊敗即勝利；神社結界耗盡即失敗。

初版建議讓神社承受 **10 次攻擊**，巫女碰到敵人時受到短暫減速與擊退，先讓失敗條件集中在守護神社。

**2. 第一版遊戲內容**

先做一場約 **5～7 分鐘、共 6 波**的完整關卡。

| 項目      | 初版設計                                     |
| --------- | -------------------------------------------- |
| 低階惡靈  | 血量少、數量多，持續逼近神社                 |
| 中階魔物  | 耐久較高，搭配少量快速敵人形成攔截壓力       |
| 最終 BOSS | 帶有攻擊預警與範圍招式，戰鬥中召喚惡靈       |
| 護符射擊  | 自動瞄準附近敵人，作為起始技能               |
| 環身御幣  | 環繞巫女，攻擊靠近的敵人                     |
| 淨化結界  | 定期在巫女周圍造成範圍傷害                   |
| 升級強化  | 提升傷害、射速、彈數、技能範圍與經驗吸收距離 |

每項技能都會有清楚的視覺差異，讓升級後的變強感能直接看見。

**3. 畫面與操作體驗**

採用**日式夜間神社、深藍夜色、朱紅鳥居與金色符咒**的視覺方向。中央神社保持醒目，敵人、經驗光玉與攻擊預警使用不同顏色與輪廓，避免混戰時難以辨識。

遊戲以整頁呈現，介面保留神社結界、波次、經驗條及技能狀態。包含開始畫面、暫停、音效開關、勝敗結算與重新挑戰。

**4. Pixi.js 的實作方式**

使用 **Pixi.js v8＋TypeScript＋Vite**。Pixi.js 負責場景、角色、動畫與戰鬥特效，HTML/CSS 負責選單和升級卡片；透過 PixiJS 的 Ticker 更新遊戲，並處理視窗尺寸變化。

程式會分開管理角色、敵人、技能、波次及遊戲狀態，技能數值集中設定，方便後續調整難度。敵人與彈體增加時，使用物件池與空間分區減少效能負擔。

**5. 開發順序與驗收**

1. **可玩原型**：完成移動、敵人進攻、自動射擊、神社受損及勝敗判定。
2. **完整成長循環**：加入經驗、升級選擇、三種技能、六波敵人與 BOSS。
3. **視聽與操作打磨**：加入正式畫面、命中特效、音效及手機操作。
4. **遊玩驗證**：確認能從開始一路玩到勝利或失敗，暫停與重玩正常，並檢查大量敵人與不同螢幕尺寸下的表現。

第一版的重點，是驗證「**離開神社收集經驗，會不會錯過回防時機**」這個取捨是否有趣。先把這個核心做完整，再擴充更多技能、敵人與關卡。

</details>

**檢查清單**

- [ ] 失敗條件：神社被打幾次就輸？
- [ ] 有幾波敵人：一共打幾波？
- [ ] 如何升級：升級時能選什麼？

**想改的話，一句話就好**，例如：

```text
神社改成被打 5 次就失敗。
```

**為什麼這樣寫**

- 「**先從規劃開始，告訴我你會怎麼做**」：就像裝潢要先看平面圖。在圖上改只要一句話，牆打掉了才改就要重做。
- 「**使用 Pixi.js**」：這是做 2D 網頁遊戲常用的工具，把畫圖、動畫這些基本功能都包好了。指定了，AI 就不用猜要用什麼。
- 這份規劃也是**驗收單**：做完之後拿出來對，就知道 AI 有沒有漏掉。

**如果和你的不一樣**

- AI 沒寫規劃，直接開始寫程式 → 叫它停：「先停下來，先給我看規劃。」
- 規劃少了什麼 → 直接問它，或叫它補上。
- 規劃裡提到 TypeScript、Vite → 那是寫網頁的工具，不用管。我們那次，它後來自己簡化成一般的 JavaScript。

## 第 2 步：主角

**目標**：先畫好主角的樣子（立繪），再做成會走路的圖。

你可能會想：「做遊戲不是要寫程式嗎？」先畫圖有兩個原因。

1. AI 寫的程式可以一直改到對，AI 畫的圖卻每次都不太一樣。**先把最難控制的東西定下來**，再讓程式配合圖。
2. 先看到自己的角色動起來，比較有動力呀～

### 2-1 立繪

**要上傳**：你的角色圖（沒有就用[角色海報](%E8%A7%92%E8%89%B2%E6%B5%B7%E5%A0%B1/Machakon-Poster-2026.jpg)）

**第 2 則提示詞**

```text
OK, 現在，我們開始製作素材。
主角巫女請以這張圖片的角色做設計。
髮型要一樣，但服裝可以重新設計成適合這個遊戲的風格。
先製作站立正面立繪、白色背景。
```

![第 2 步的畫面](%E5%9C%96%E8%A7%A3/step2-send.jpg)

① 把角色圖拖進**同一個對話串** → ② 貼上提示詞 → ③ 送出

**你會看到**：一張白色背景、從頭到腳的正面立繪。

<img src="%E5%AD%98%E6%AA%94%E9%BB%9E/%E6%AD%A5%E9%A9%9F2-%E5%B7%AB%E5%A5%B3%E7%AB%8B%E7%B9%AA.png" alt="我們的巫女立繪" width="280">

**檢查清單**

- [ ] 髮型髮色：跟你的角色一樣嗎？
- [ ] 全身入鏡：頭到腳都有嗎？
- [ ] 白色背景：乾淨的白底

**為什麼這樣寫**

- 「**髮型要一樣，但服裝可以重新設計**」：講清楚哪裡不能動、哪裡可以發揮。沒講的話，它可能把參考圖的衣服整套照搬，或是把整個人換掉。
- 「**先製作站立正面立繪、白色背景**」：就像演員開拍前的定裝照。先定好樣子，後面每一格才會是同一個人。

### 2-2 會走路的圖集（spritesheet）

**第 3 則提示詞**（不用上傳，接著貼就好）

```text
非常好。
現在，依據這個角色設計圖，製作出Q版的，可供遊戲使用的 spritesheet 素材圖。
請先分析遊戲 spritesheet 的設計重點、收集參考資料，再開始製作。
```

**你會看到**：一張大圖，裡面切成 4×4 共 16 格。一列是一個方向，一列有四格走路動作。

![巫女圖集：由上到下是朝下、朝左、朝右、朝上](%E5%9C%96%E8%A7%A3/step2-atlas.jpg)

四格輪流播放，她就走起來了：

![四個方向的走路動畫](%E5%9C%96%E8%A7%A3/step2-walk.gif)

> 圖裡的背景色、格線和文字，是為了說明才加上去的。真正的[圖集檔案](%E5%AD%98%E6%AA%94%E9%BB%9E/%E6%AD%A5%E9%A9%9F2-%E5%B7%AB%E5%A5%B3%E5%9C%96%E9%9B%86.png)是透明背景，什麼都沒有。

**檢查清單**

- [ ] 四排方向：由上到下：朝下、朝左、朝右、朝上
- [ ] 十六格同一人：每一格都是同一個造型
- [ ] 透明背景：沒去掉就跟它說「請把背景改成透明」

**為什麼這樣寫**

- **spritesheet（精靈圖）** 就是把分解動作排成一大張圖，遊戲再一格一格播放。走一步是：左腳在前、交錯、右腳在前、交錯，剛好四格一個循環。
- 「**Q 版**」：角色在遊戲裡只有一百多個像素，頭大一點才認得出來。
- 「**請先分析設計重點、收集參考資料，再開始製作**」：先叫它做功課。我們那次它去查了 PixiJS 和 Aseprite 的官方文件，列出四個重點，其中一個是：側馬尾左右不對稱，所以左右要分開畫，不能直接翻過來用。

**如果和你的不一樣**

- 背景沒有去掉 → 「請把背景改成透明」
- AI 說圖的尺寸除不盡（我們的是 1254 px，分四格是 313.5 px）→ 不用重畫，第 6 步寫程式時會自動處理。
- 一直畫歪，或免費額度用完了 → 下載 [步驟2-巫女圖集.png](%E5%AD%98%E6%AA%94%E9%BB%9E/%E6%AD%A5%E9%A9%9F2-%E5%B7%AB%E5%A5%B3%E5%9C%96%E9%9B%86.png)，拖進同一個對話串，貼上這句：

```text
這是主角的 spritesheet，四乘四，由上到下是朝下、朝左、朝右、朝上。之後請用這張。
```

## 第 3 步：背景

**目標**：畫一張戰場地圖。

**第 4 則提示詞**

```text
非常好，現在，製作這個遊戲所要使用的背景圖片。
請先分析這遊戲遊玩時的視角，然後列下場景地圖的製作重點、正確的長寬比例，再開始繪製。
```

**你會看到**：AI 先說它選了什麼視角、列出製作重點，然後畫出地圖。

![我們的背景：夜晚的神社](%E5%AD%98%E6%AA%94%E9%BB%9E/%E6%AD%A5%E9%A9%9F3-%E8%83%8C%E6%99%AF.png)

**檢查清單**（AI 自己列的重點，拿來對答案）

- [ ] 視角：略帶俯角的固定視角，角色走到哪裡大小都一樣
- [ ] 四個方向：神社在中央，上下左右都有路
- [ ] 地面：低對比、少花紋，不然角色和經驗球會糊在一起
- [ ] 比例：16:9，跟遊戲畫面一樣寬

**為什麼這樣寫**

- 「**先分析這遊戲遊玩時的視角**」：視角就是攝影機擺在哪裡。如果選到有明顯遠近感的視角，主角走到上面就會變成一顆芝麻。我們那次它選了「略帶俯角的固定視角」，走到哪裡大小都一樣。
- **地板低調一點比較好**。太花的話，角色、敵人、經驗球全部會糊在一起。
- **地圖一畫好，玩法也定了**：神社在中間、四邊都有路，所以敵人會從四面八方來，下一步的敵人也要畫四個方向。

**如果和你的不一樣**

- 尺寸和它說的不一樣 → 我們那次說好 1536×864，實際給 1672×941。比例差不多就沒關係。
- 在第 1 步換了題材 → 這則提示詞不用改，它會照你的企畫畫。

- [ ] 顏色分得開：不要跟綠色的經驗球混在一起

**檢查清單**

- [ ] 只有正面：不會轉身，不用背面
- [ ] 每招都有預警：紅圈、聚氣、仰頭吸氣
- [ ] 體型夠大：比小怪大好幾倍
- [ ] 背景是透明的：灰底就再去背一次

**為什麼這樣寫**

- 「**不會轉身，不會有背面的角度**」：前面都畫四個方向，AI 會照習慣一直畫下去。**不需要的也要講**，省下來的力氣就能拿去畫招式。
- 「**先分析它如何出招**」：每一招都要有預警，玩家才閃得掉；閃掉了，才會覺得是自己厲害。

  <img src="%E5%9C%96%E8%A7%A3/step5-warning.jpg" alt="遊戲裡的紅圈預警" width="420">
- AI 還自己想到兩件事：鬼王很大隻，可是**被打到的範圍只算腳下**，不然玩家靠不過去；紅圈和鬼火**交給程式畫**，要調大小只要改數字。

**如果和你的不一樣**

- BOSS 帶著灰色背景 → 「請再去背一次」
- 想加招式 → 在提示詞後面加一句，例如「其中一招要會分身」。

### 7-2 做錯的：用條列的方式告訴 AI

先**自己玩一次**，打到鬼王，記下你不喜歡的地方。我們玩完發現三個問題：鬼王的血條擋住牠的臉、結界和經驗只有數字看不清楚、傷害數字疊成一團。

**第 10 則提示詞（範例，不要照抄）**

```text
目前的 UI（使用者界面）有這些問題，請分析並開始優化：
1. 鬼王血條移到畫面最上方，改成整條橫的（目前 BOSS 的血條會擋住它的臉）；
2. 結界和經驗從數字改成條狀；
3. 傷害數字不要疊成一團。
```

這是我們的問題，你的一定不一樣。**照這個寫法，寫你自己的**：

```text
目前的＿＿有這些問題，請分析並開始優化：
1. ＿＿改成＿＿（目前＿＿）；
2. ＿＿改成＿＿（目前＿＿）；
```

1. 開頭寫「請分析並開始優化」。
2. 編號，一條一個問題。
3. 每條寫你想要它變成什麼。
4. 括號補一句「目前發生什麼」。

**第 4 點最重要。** 這是我們送出前的草稿和送出的版本：

![草稿與送出版](%E5%9C%96%E8%A7%A3/step7-draft.jpg)

「搬到最上面」是你想的**解法**，「擋住臉」才是**問題**。AI 知道問題是什麼，搬完之後才會想到檢查：新位置有沒有又擋到？

**你會看到**：我們那次處理了 6 分 3 秒，三條都改好了，還自己多做了「結界危急時變紅」和「連擊合併顯示」。

![AI 的回報](%E5%9C%96%E8%A7%A3/step7-done.jpg)

![鬼王的臉露出來了](%E5%9C%96%E8%A7%A3/step7-face.jpg)

再看整個畫面：

![改之前與改之後的整個畫面](%E5%9C%96%E8%A7%A3/step7-before-after.jpg)

右邊那張，左右多了黑邊：資訊列搬到上面，把戰場擠小了。**修好一個、擠壞另一個，很正常**。要不要再修，由你決定，用同樣的寫法就可以。

**檢查清單**

- [ ] 聲音：開始畫面、一般戰鬥、鬼王戰會換曲
- [ ] 音量：音樂和音效可以分開調
- [ ] 靜音：有靜音開關
- [ ] UI：血條、結界、經驗不擋臉、看得清楚
- [ ] 你自己的問題：玩一次，找出你不喜歡的地方

**改壞了怎麼辦？**

```text
請把剛剛的修改還原。
```

然後把問題拆開，**一次只改一條**，就知道是哪一條改壞的。

## 七步食譜

大部分的遊戲，都可以用這個流程來做。

| 步驟      | 一句話重點                         |
| --------- | ---------------------------------- |
| 1. 規劃   | 先寫規劃，不要馬上做               |
| 2. 主角   | 先定裝，再做動作                   |
| 3. 背景   | 先分析視角，地面要低調             |
| 4. 敵人   | 拿做好的當標準：「比剛剛的強一點」 |
| 5. BOSS   | 講清楚「不要什麼」，出招要有預警   |
| 6. 第一版 | 先做最小能玩的，再慢慢改善         |
| 7. 修問題 | 一條一個問題，講「現在發生什麼」   |

### 這些寫法，做別的東西也能用

| 寫法               | 例子                                   | 用意                       |
| ------------------ | -------------------------------------- | -------------------------- |
| 先分析，再動手     | 「先從規劃開始，告訴我你會怎麼做」     | 先看到它的想法，不對就先改 |
| 一次只做一樣       | 主角、背景、敵人分開做                 | 出問題知道是哪一步         |
| 先定造型，再做動作 | 「先設計造型，然後再製作 spritesheet」 | 每一格才會是同一個角色     |
| 講清楚什麼不能動   | 「髮型要一樣，但服裝可以重新設計」     | 保留你在意的，其他讓它發揮 |
| 拿做好的來比較     | 「比剛剛的惡靈稍微強一點」             | 比形容詞準                 |
| 講清楚不要什麼     | 「不會轉身，不會有背面的角度」         | 不然它會照習慣做           |
| 第一版刻意做小     | 「UI 可以先用數字的方式呈現」          | 先能玩，再變好看           |
| 講問題，不只講解法 | 「（目前 BOSS 的血條會擋住它的臉）」   | 它才會自己檢查             |

## 換成你自己的題材

### 1. 先回答三個問題

| 問題                 | 神社保衛戰     | 例如：貓咪守冰箱           |

### 2. 改寫企畫

下載[遊戲企畫-空白範本.txt](%E9%81%8A%E6%88%B2%E4%BC%81%E7%95%AB-%E7%A9%BA%E7%99%BD%E7%AF%84%E6%9C%AC.txt)，把括號換成你的答案，第 1 步上傳這一份：

```text
《你的遊戲名稱》

遊戲介紹：（用兩三句話寫：誰、在哪裡、遇到什麼危機）

玩家操作對象：（主角）

敵人：低階（很弱、很多的）、中階（比較強的）、高階BOSS（大魔王）

```

## 加分作業

還沒玩夠嗎？這三題都用得到前面學過的寫法：

1. **打擊感**：打到敵人的時候，讓牠閃一下、畫面震一下。（用第 7 步的寫法）
2. **增加第三種敵人**。（用第 4 步的「比剛剛的……稍微強一點」，做完圖再請 AI 加進遊戲）
3. **把主角換成另一個角色**。（從第 2 步再做一次）

## 常見問題

**要會寫程式嗎？**
不用。你要做的是決定、檢查、講清楚。

**免費版可以嗎？**
勉強可以，但額度比較少。不夠的話，可以用[存檔點](%E5%AD%98%E6%AA%94%E9%BB%9E/)的圖跳過畫圖，直接做第 6、7 步。

**一定要一口氣做完嗎？**
不用。我們第 1～6 步和第 7 步就是分兩天做的。隔天打開同一個對話串，接著貼就可以。

**我做出來的和你們差很多？**
正常的～ AI 每次做的都不一樣。對照檢查清單，有過就好。

**AI 說「完成了」「測試通過了」，可以相信嗎？**
可以參考，但一定要自己看一遍、玩一遍。

**可以用這裡的圖和聲音做我自己的遊戲嗎？**
可以。聲音是 CC0，不用署名；程式是 MIT，保留授權聲明就好；圖片是 CC BY-NC 4.0，要署名「抹茶小語」，而且不可商用。你自己用 ChatGPT 畫出來的圖，不受這裡的授權限制（如果是拿角色海報改的，還是要照海報的授權）。詳細請看[授權與來源](#授權與來源)。

**我想自己找音效和音樂，去哪裡找？**
音效看[這份說明](%E9%9F%B3%E6%95%88/README.md)。音樂看[獨立遊戲 BGM 的五條路](BGM/README.md)：免費素材、只能放在自己遊戲裡的素材、要署名的、AI 作曲、自己作曲。每一條的授權規定不一樣，使用前請到原網站確認。
